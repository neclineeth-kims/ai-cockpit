# Kararlar Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ajanların sorduğu soruları, verilen cevapları, plan onaylarını ve tasarım dosyalarını proje bazında gösteren Kararlar sayfası; iç model AG-UI interrupt/resume şeklinde.

**Architecture:** Yeni veri toplanmaz. `events` tablosu yalnız hangi oturumda soru, plan onayı ya da dosya yazımı olduğunu bulmak için kullanılır (`tool_name` indeksi). İçerik, o oturumların Claude Code dökümünden (`sessions.transcript_path`, JSONL) okunur: `server/lib/decisions.js` dökümü satır satır tarar, sonucu dosya boyutu ve değişme zamanıyla önbelleğe alır, `Decision` nesnelerine çevirir. `server/routes/decisions.js` sunar, `client/src/pages/Decisions.tsx` gösterir. Proje, oturum `cwd`'sinin `workRepo` sonucu (plan.js).

**Tech Stack:** Node (node:test), better-sqlite3, `readline` (stdlib), React + i18n (6 dil), Vitest.

**Spec:** `docs/superpowers/specs/2026-11-16-kararlar-design.md`

## Veri kaynağı (17 Kasım ölçümü)

Spec `events.data.tool_input` içinde soru ve cevap olduğunu varsaymıştı. Gerçek veride:

- `AskUserQuestion` için 707 PostToolUse olayının 676'sı `{"imported": true}`, içeriksiz. Yalnız 31'inde `tool_input.questions` ve `answers` var.
- `ExitPlanMode` için 15 olayın hepsi içeriksiz.
- `Write` ve `Edit` için 17.582 olayın 16.433'ü içeriksiz, `file_path` yok.

Dökümde hepsi tam olarak duruyor:

- Assistant satırı: `message.content[]` içinde `{type:"tool_use", id, name, input}`.
  - `AskUserQuestion` input: `{questions:[{question, header, multiSelect, options:[{label, description}]}]}`.
  - `ExitPlanMode` input: `{plan, planFilePath}`.
  - `Write`/`Edit`/`MultiEdit` input: `{file_path, ...}`.
- Cevap satırı: `message.content[]` içinde `{type:"tool_result", tool_use_id, is_error?, content}`, satırın kökünde `toolUseResult`.
  - Soru: `toolUseResult = {questions, answers: {"<soru metni>": "<cevap>"}, annotations?: {"<soru metni>": {notes?}}}`.
  - Plan onayı: `toolUseResult = {plan, filePath, isAgent}`; red ise `is_error: true` ve `content` metni "The user doesn't want to proceed..." ile başlar, kullanıcının notu sonrasındadır.
- Her satırda `timestamp` (ISO) var. Eşleşme `tool_use_id` ile kesin; spec'teki "oturum + metin + sıra" yedeğine gerek kalmaz.

Codex ve Cursor dökümleri bu planın dışında (spec "Kapsam dışı").

## Global Constraints

- Yeni bağımlılık yok; AG-UI'den yalnız veri şekli alınır.
- Veri makineden çıkmaz; dışa aktarım yalnız kullanıcı tıklamasıyla, dosya indirme olarak.
- Arayüz metinleri 6 dilde (tr, en, vi, zh, ko, es).
- Brief'e giren karar bölümü en çok 4096 bayt; brief toplam tavanı 32 KB (`capBrief`) korunur.
- Döküm okuma salt okunur; döküm dosyasına yazılmaz.
- Testler gerçek `~/.claude` ya da gerçek `dashboard.db`'ye dokunmaz: geçici dizin, `DASHBOARD_DB_PATH` ve `DASHBOARD_DATA_DIR` ile (api-errors.test.js deseni).

## Review Focus

1. Cevap metni seçeneklerden biri değil, "Other" ile yazılmış serbest metin: aynen gösterilir, `other: true`. Test: Task 1 `free text answer`.
2. `multiSelect` cevabı `", "` ile birleşik tek string; seçenek etiketinin kendisi virgül içerebilir. Önce tam eşleşme, sonra parçalar. Test: Task 1 `multiSelect answer with comma in label`.
3. tool_use var, tool_result yok: oturum `active` ve dökümde sonrasında satır yoksa `pending`, değilse `cancelled`. Test: Task 1 `unanswered question`.
4. 100 MB'lık döküm: dosya satır satır okunur, yalnız ilgili satırlar `JSON.parse` edilir, ikinci çağrıda aynı boyut ve mtime için dosya yeniden okunmaz. Test: Task 1 `scan is cached by size and mtime`.
5. Tasarım dosyası açma uç noktası: `..`, sembolik bağ ya da proje dışı yol 404 döner, dosya içeriği sızmaz. Test: Task 3 `design file outside project`.
