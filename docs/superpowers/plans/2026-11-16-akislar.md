# Akışlar Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Depoda tanımlı akışları (agent, script, gate adımları) iş tahtası görevlerinin worktree'sinde adım adım yürüten, insan kapılarını Kararlar sayfasında soran motor ve ekran.

**Architecture:** Motor kokpit sunucusunun içinde çalışır; `server/lib/flows/` altında ayrıştırıcı, durum deposu (SQLite tablosu `flow_runs`, `flow_steps`) ve yürütücü. Ajan adımları mevcut spawner'larla başsız çalışır. Kapılar Kararlar modeline yazılır. Ekran: görev satırında akış durumu ve yeni Akış koşusu detay sayfası.

**Tech Stack:** Node (node:test), js-yaml 4.3.1 (zaten bağımlılık), React + i18n (6 dil), Vitest.

**Spec:** `docs/superpowers/specs/2026-11-16-akislar-design.md`
**Önkoşul:** Kararlar planı Task 1-3 (Decision modeli ve API).

## Global Constraints

- Yeni bağımlılık yok; YAML için mevcut js-yaml (`yaml.load`, varsayılan güvenli şema).
- Push, PR ve issue yazımı yalnız bir kapıdan sonra ve önizleme ile.
- `script` adımları depo bazında ilk çalıştırmada onaylanır.
- Arayüz metinleri 6 dilde.

## Review Focus

1. Sunucu akış ortasında yeniden başlatılırsa: çalışan adım "kesildi" olur, akış o adımdan sürdürülebilir; aynı adım iki kez başlamaz.
2. Kapıdan geri gönderilen adım: önceki çıktısı saklanır, yeni tur numarası alır, `en_cok_tur` aşılınca akış kapıda durur.
3. Ajan sıfır kodla çıkar ama beklenen `cikti` dosyası yok: adım hata.
4. Aynı görevde iki akış aynı anda başlatılmak istenirse: ikincisi reddedilir.
5. Maliyet tavanı aşılırsa: yürütücü yeni adım başlatmaz, akış kapıda durur.

---

### Task 1: Akış dosyası ayrıştırıcı ve doğrulama (est:3h)

- [ ] Adım türleri, `girdi`/`cikti` zinciri, `basarisizsa` ve `geri_gonderilebilir` hedeflerinin var olan adımlar olması, döngü sınırı.
- [ ] Hatalı dosyada satır ve alan adıyla Türkçe hata.

### Task 2: Durum deposu (est:2h)

- [ ] `flow_runs` (görev, akış adı, durum, başlangıç, maliyet) ve `flow_steps` (adım, tur, durum, çıkış kodu, log yolu, süre, maliyet) tabloları ve göçü.
- [ ] Sunucu açılışında "çalışıyor" kalmış adımları "kesildi" yap.

### Task 3: Yürütücü: agent ve script adımları (est:5h)

- [ ] Ajan adımı: rol dosyası + brief + girdi dosyaları ile istem; mevcut spawner başsız; çıktı dosyası kontrolü.
- [ ] Script adımı: depo onayı, worktree'de çalıştırma, zaman aşımı, log.
- [ ] `basarisizsa` dönüşü ve `en_cok_tur`.
- [ ] Adım maliyetini oturum maliyetinden topla; tavan kontrolü.

### Task 4: Kapılar ve Kararlar bağlantısı (est:3h)

- [ ] `gate` adımı `Decision` üretir (`reason: confirmation`, `metadata.kind: gate`).
- [ ] `POST /api/flows/:runId/gate` ile onay ya da seçilen adıma geri gönderme (not ile).
- [ ] Kararlar Bekleyen sekmesinde kapı kartı: gösterilen dosyalar, Onayla, Geri gönder.

### Task 5: Hazır şablonlar ve rol istemleri (est:2h)

- [ ] Önce `inceleme-turu` (İncele, Düzelt, Yeniden incele, Kabul kapısı) ve rol dosyaları (inceleyici, düzeltici); motorun uçtan uca testi bu şablonla.
- [ ] Sonra `ozellik` ve `hata`: Netleştir/Yeniden üret adımından sonra plan onayı kapısı, sonda Kabul kapısı.
- [ ] "Akışları depoya ekle" düğmesi şablonları `.ai-cockpit/akislar/` altına kopyalar; kullanıcı commit'ler.

### Task 6: Görsel taslak (est:2h)

- [ ] Görev satırında akış durumu, akış koşusu detay sayfası (adım şeridi, log, çıktı dosyaları, yeniden dene ve buradan başlat), kapı kartı.
- [ ] Kullanıcı onayı olmadan Task 7'ye geçilmez.

### Task 7: Ekran (est:5h)

- [ ] İş tahtası ve Plan görev satırında "Akışla başlat" ve durum rozeti.
- [ ] Akış koşusu sayfası: onaylı taslağa uygun.
- [ ] Yeniden dene, buradan başlat, durdur.

### Task 8: Kılavuz (est:1h)

- [ ] NASIL_KULLANILIR.md'ye Akışlar bölümü; akış dosyası başvuru tablosu.
